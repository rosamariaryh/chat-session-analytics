# chat-session-analytics

An application which analyzes chatbot conversations and extracts both deterministic and AI-powered insights.

## Overview

This project processes chatbot conversation sessions from raw JSONL data and produces classified session-level results and run-level summaries.

The pipeline consists of:

1. **Validation** — checks the input data for expected structure and quality.
2. **Deterministic metrics** — calculates metrics directly from the conversation data.
3. **LLM classification** — uses Gemini to classify each valid session.
4. **Merge results** — combines deterministic metrics and LLM classifications.
5. **Output** — produces classified sessions in JSONL and CSV format, together with a run-level summary.

The goal is to combine **reproducible, deterministic measurements** with **AI-powered qualitative classification** to provide a richer view of chatbot usage.

## Set up

### Environment variables
Ensure you have the following environment variables set in your .env file:

- `GEMINI_API_KEY=`
- `GEMINI_MODEL_NAME=`
- `GEMINI_FALLBACK_MODEL=`

See `.env.example` for the required environment variables.

### Dependencies
This project uses [uv]([https://docs.astral.sh/uv/](https://docs.astral.sh/uv/)) for packaging and library management.

1. Ensure uv is installed

`uv --version`

2. Create virtual environment and install dependencies. From the project root, run:

`uv sync`

3. Activate virtual env

macOS / Linux / Git Bash: `source .venv/Scripts/activate`
Windows PowerShell: `.venv\Scripts\Activate.ps1`

> You can also run all scripts with `uv run <script_name>` without activating the virtual environment

4. Add new dependencies if needed

`uv add pandas`

## Usage

### Run the pipeline

The pipeline accepts a JSONL file containing chatbot sessions.

From the project root:

`uv run python main.py <input_file>`

For example:

`uv run python main.py data/raw/mock_chat_sessions_150.jsonl`

The input file is processed session-by-session through validation, deterministic metric calculation, LLM classification, and result merging.

### Input data

The pipeline expects a JSONL file, where each line represents a chatbot conversation session.

Example:

```
{"session_id": "session_001", "messages": [...]}
{"session_id": "session_002", "messages": [...]}
{"session_id": "session_003", "messages": [...]}
```

Each session is validated before being processed.

Invalid sessions are not sent to the LLM classification step.

### Results

The deterministic metrics and LLM classifications are merged into a single result for each valid session.

Each classified session contains both:

Deterministic metrics calculated from the source data
AI-powered classifications generated by Gemini

### Outputs

The pipeline produces two types of output.

#### Classified sessions

Session-level results are exported in:

- JSONL — one classified session per line
- CSV — tabular representation of the classified sessions

These outputs contain the combined deterministic and LLM-generated attributes.

#### Run-level summary

A run-level summary provides aggregate information about the processing run, including counts and statistics across the processed sessions.

This provides a high-level view of the dataset without requiring the individual session results to be inspected.
